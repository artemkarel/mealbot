# Приложение для плана питания

Мини-приложение в Telegram: пересылаешь боту файл от диетолога — получаешь план по дням,
список закупок с делением по срокам хранения и расчёт готовки в сыром и готовом весе.

Парсер проверен на трёх реальных планах: 7/7 дней, 35/35 приёмов, все позиции.

---

ssh твой-сервер

## Шаг 3. Заполни справочник — главная работа

Это единственное, что нельзя автоматизировать, и без этого не работает ничего остального.
Заготовки уже собраны из твоих трёх планов, править их проще, чем писать с нуля.

### `data/products.csv` — товары

```
id;name;shelf_days;freezable;category;pack;unit;url
grechka;Гречка ядрица;365;0;Крупы и мука;800;г;https://vkusvill.ru/...
file_lososya;Филе лосося охлаждённое;2;1;Рыба;;г;
```

- `shelf_days` — сколько дней хранится после покупки. От этого зависит деление закупок
- `freezable` — 1 если можно заморозить
- `pack` — размер упаковки, чтобы округлять («не 130 г творога, а пачка 200 г»)
- `url` — ссылка на товар. В планах их уже 11–27 штук, забери их оттуда

### `data/dishes.csv` — из чего состоит блюдо

```
dish;type;product;amount;unit;coef;note
Отварная гречка;блюдо;grechka;;;2.2;
Запечённое филе лосося;блюдо;file_lososya;;;0.8;
Хлебцы из зелёной гречки с козьим сыром;блюдо;hlebcy;1;шт;;
Хлебцы из зелёной гречки с козьим сыром;блюдо;kozy_tvor;20;г;;
```

**Одна формула на все случаи:** `coef` = вес готового ÷ вес сырого.

| Продукт | coef | Почему |
|---|---|---|
| Гречка | 2.2 | 82 г крупы дают 180 г каши |
| Рис, киноа | 3.0 | разбухает втрое |
| Булгур | 2.6 | |
| Макароны, лапша | 2.5 | |
| Рыба, мясо запечённые | 0.8 | усыхает примерно на пятую часть |
| Котлеты на пару | 0.85 | |

Дальше приложение само считает: `сырой вес = вес из плана ÷ coef`.
В магазин идёт сырой вес, на тарелку — вес из плана.

Если блюдо составное, пиши **несколько строк с одинаковым `dish`** и заполняй `amount`
вместо `coef` — тогда coef не нужен.

**Что делать:** открой `data/dishes.csv` в Excel или Numbers. 72 строки помечены `ПРОВЕРЬ` —
пройди по ним и убери пометку, когда проверил. Начни с тех блюд, что есть в плане на
эту неделю, остальные дозаполнишь потом.

После каждой правки:

```bash
python seed.py
```

## Шаг 4. Залей на сервер

```bash
ssh твой-сервер
sudo mkdir -p /opt/mealplan && sudo chown $USER /opt/mealplan
git clone https://github.com/твой/репозиторий /opt/mealplan
cd /opt/mealplan
python3 -m venv venv
venv/bin/pip install -r requirements.txt
venv/bin/python seed.py
```

Создай `.env` (тот самый токен из шага 0):

```bash
cp .env.example .env
nano .env
```

```
BOT_TOKEN=1234567:AAxxxxxxxx
WEBAPP_URL=https://твой-домен/
ALLOWED_USER_IDS=123456789
DB_PATH=data/mealplan.db
REMIND_MORNING=07:30
REMIND_EVENING=21:00
```

`ALLOWED_USER_IDS` — твой Telegram ID. Без него приложением сможет пользоваться кто угодно,
кто узнает адрес. Напоминания бот шлёт тоже только этим пользователям.
`REMIND_MORNING` — что взять с собой + что съесть по сроку; `REMIND_EVENING` — что
подготовить на завтра и когда готовить сразу на два дня. Время по часам сервера.

Останови старый сервис и подними два новых:

```bash
sudo systemctl stop mealbot && sudo systemctl disable mealbot
sudo cp deploy/*.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now mealplan-web mealplan-bot
sudo systemctl status mealplan-web mealplan-bot
```

Оба должны быть `active (running)`. Если нет — смотри, что не так:

```bash
journalctl -u mealplan-web -n 50
journalctl -u mealplan-bot -n 50
```

HTTPS на сервере делает Caddy. Весь трафик идёт на порт 8080:

```
zdorovaedabot.duckdns.org {
    reverse_proxy 127.0.0.1:8080
}
```

```bash
sudo caddy validate --config /etc/caddy/Caddyfile && sudo systemctl reload caddy
```

В Telegram открой `@BotFather`:

2. **Bot Settings** → **Menu Button** → **Configure menu button**
3. Вставь адрес: `https://твой-домен/`

## Шаг 6. Проверь

Открой своего бота, напиши `/start`, перешли ему файл с планом от диетолога.
Бот должен ответить «План загружен». Нажми кнопку — откроется приложение.

## Что делать каждую неделю

Одно действие: приходит файл от диетолога — пересылаешь его боту. Всё.

Если бот напишет «Нет в справочнике» и перечислит названия — допиши их
в `data/dishes.csv`, закоммить и на сервере запусти `./update.sh`.

## Что уже работает

- Разбор `.docx` без pandoc, включая мягкие переносы внутри абзаца
- Поиск одинаковых дней — в плане 10–16 августа их три пары
- Извлечение рецептов, ссылок на товары и фраз про подготовку заранее
- Пересчёт сырого и готового веса
- Список закупок с делением на две части по срокам хранения
- Множитель на количество человек
- Проверка `initData` и белый список пользователей
- Фронтенд на живом API: сегодня / неделя / готовка / закупки, отметки «съедено», рецепты
- Разбор пакетов: покупки записываются в `purchases`, сроки годности считаются
  от даты покупки, экран «Холодильник» показывает, что съесть первым
- Напоминания в боте: утром — что взять с собой и что истекает по сроку,
  вечером — что подготовить на завтра и когда готовить сразу на два дня
