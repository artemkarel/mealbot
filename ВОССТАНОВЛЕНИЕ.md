## 5. Справочник — сердце проекта

Без него не работает ничего: ни закупки, ни КБЖУ, ни готовка. Три CSV-файла
с разделителем `;` (не запятая!).

### `data/products.csv` — товары (120 строк)

```
id;name;shelf_days;freezable;category;pack;unit;url;kcal;prot;fat;carb;unit_g;search
grechka;Гречка ядрица;365;0;Крупы и мука;800;г;;313;12.6;3.3;62;1;гречка ядрица
```

- `pack` — размер упаковки для округления закупки;
- КБЖУ — **на 100 г сырого продукта**;
- `unit_g` — сколько граммов в одной штуке (для товаров, что план меряет в штуках);
- `search` — короткий запрос для поиска в магазине (1–3 слова, строчными).

### `data/dishes.csv` — из чего состоит блюдо (280 строк)

```
dish;type;product;amount;unit;coef;note
Отварная гречка;блюдо;grechka;;;2.2;
Зеленый салат;блюдо;rukkola;30;г;;порция 140 г
Зеленый салат;блюдо;pomidory_cherri;50;г;;
Горячая вода;напиток;;;;;
```

Правила:

- **одиночное блюдо**: одна строка, `amount` и `unit` пустые, `coef` = вес готового ÷ вес
  сырого. Варка круп 2.2–3.0, запекание мяса 0.7–0.8, пар 0.8;
- **составное блюдо**: несколько строк с одинаковым `dish`, у каждой `product` + `amount`
  на одну порцию;
- **напиток** (вода, чай, кофе): `type=напиток`, `product` пустой — скрыт из закупок;
- **готовый покупной продукт**: `type=товар`, всё пусто — считается 1:1;
- `coef < 1` **из-за очистки** (кожура, корка, семена) требует слова «очистка», «кожура»,
  «корка» или «семена» в `note`. На этом слове держится честный расчёт калорий: несъедобная
  часть не несёт калорий, но покупается (дыня 250 г = 88 ккал, а не 146);
- `ПРОВЕРЬ:` в `note` — прикидка, которую стоит однажды сверить с реальностью.

### `data/store_links.csv` — карточки товаров в магазинах (336 строк)

```
product;store;url;name;confidence
grechka;vkusvill;https://vkusvill.ru/goods/krupa-grechnevaya-yadritsa-17699/;Крупа гречневая ядрица, 900 г;high
```

Магазины: `vkusvill` (108), `lenta` (73), `magnit` (77), `lavka` (78).

### `data/vv_items.csv` — единицы карточек ВкусВилл (108 строк)

```
product;xml_id;unit;weight_kg;price;name;pcs
perepelinye_yayca;96131;шт;0.12;227;Яйцо перепелиное пищевое фермерское 20шт;20
```

Нужен, чтобы посчитать, сколько заказать: упаковок или килограммов.
`xml_id` — число в конце URL карточки ВкусВилл.

**После любой правки CSV — `./venv/bin/python seed.py`.**

## 6. База данных

SQLite, схема в `schema.sql`, миграции — в `_migrate()` в `app/db.py` (ALTER-ы для старых баз).

Таблицы: `products`, `dishes`, `store_links`, `vv_items` (справочники);
`plans`, `plan_items`, `plan_links`, `recipes`, `prep_tasks` (планы);
`user_prefs`, `user_reminders`, `supplements`, `user_recipes`, `user_places`,
`meal_logs`, `meal_overrides`, `week_plans`, `menu_share`, `users`, `settings`, `purchases`.

Ключевые механики:

- **`week_plans`** — какой план на какую неделю (`week_start` всегда понедельник).
  `plan_for(con, uid, date)` — резолвер: свой выбор → выбор владельца общего меню →
  текущий план. На будущую неделю без плана вернёт `None`;
- **`menu_share`** (owner → follower) — Эльвина видит планы Артёма;
- **`meal_overrides`** — замена или добавление приёма пищи целиком. Сиротская запись
  (приёма нет в плане) означает добавленный приём;
- **`day_items(con, uid, plan_id, day)`** — единственная правильная точка получения
  позиций дня: подставляет замены и сортирует приёмы. Используй её везде.

Соединение — **одно на поток** (`threading.local` в `app/db.py`). Раньше каждый запрос
открывал новое и не закрывал: бот за полсуток упирался в лимит открытых файлов и падал.

## 7. Магазины и корзины

Режим «Закупки → По магазинам» раскладывает список по минимальному числу магазинов
(жадный алгоритм `planBaskets` в `web/index.html`): товар едет в самую крупную корзину,
где есть его карточка. Корзины меньше трёх позиций расформировываются.

### ВкусВилл — единственный, где корзина собирается автоматически

Официальный MCP-сервер: `https://mcp001.vkusvill.ru/mcp`, stateless JSON-RPC по POST.
**Обязателен браузерный User-Agent**, иначе 403 «Access Blocked». Ключей не нужно.

Инструменты: `vkusvill_products_search`, `vkusvill_product_details`,
`vkusvill_cart_link_create`, `vkusvill_product_analogs`, `vkusvill_recipes`,
`vkusvill_shops`, `vkusvill_products_discount`, `vkusvill_product_barcode`.

`cart_link_create` отдаёт ссылку `https://vkusvill.ru/?share_basket=…`, которая открывает
сайт или приложение с уже заполненной корзиной. Проверено живьём:

- **вторая ссылка заменяет корзину целиком**, а не дополняет её;
- реальный лимит — **30 позиций** на ссылку (в описании схемы написано 20, но сервер
  принимает 30 и отклоняет 31);
- количество: упаковки для `unit = шт`, килограммы с шагом 0.1 для `unit = кг`.

Считать количество нужно **от сырой потребности** (`early + late` из `build()`), а не от
`qty.value`, уже округлённого под нашу фасовку, и агрегировать по `xml_id` **до**
округления. Иначе выходит двойное округление и лишние упаковки (ловилось: 5 пачек лапши
вместо 3, 2 банки маслин на 30 г).

### Остальные магазины — только поиск по ссылке

Лента, Перекрёсток, Пятёрочка, Магнит, Самокат, Яндекс Лавка, Купер: открывается страница
поиска по названию товара, дальше руками. Шаблоны URL — в массиве `STORES` в
`web/index.html`, все проверены.

- Перекрёсток, Пятёрочка, Самокат, Купер закрыты антиботом Servicepipe — их каталог
  снаружи не читается, карточки подобрать нельзя;
- внутренний API Ленты (`POST /api-gateway/v1/catalog/items`) работал в августе 2026,
  с сентября отдаёт 403, гостевой токен не выдаётся. Карточки Ленты остались от старого
  сбора, новые добавить нечем.

## 9. Грабли, на которых уже наступали

**Окружение**

- На компьютере системный Python 3.9 — код должен быть с ним совместим
  (`from __future__ import annotations` там, где аннотации `X | None`).
  На сервере 3.14;
- git на маке ломается без лицензии Xcode. Обход:
  `DEVELOPER_DIR=/Library/Developer/CommandLineTools git …`;
- `pkill -f "app.main"` убивает собственную ssh-сессию. Писать `pkill -f "app[.]main"`;
- локальный сервер поднимать только с `DEV=1`, иначе 401 на все запросы.

**Данные**

- `seed.py` удаляет сначала `dishes`, потом `products` — из-за внешнего ключа;
- кэш справочника в `app/ref.py` инвалидируется по `PRAGMA data_version`, а не по времени
  файла: в режиме WAL mtime не меняется;
- **ИИ-агенты в фоновых задачах могут сделать `git checkout` рабочих файлов и откатить
  несохранённые правки CSV.** После любого многоагентного прогона проверяй `git status`
  и `wc -l data/*.csv`, коммить сразу.

**Логика**

- приёмы пищи берутся только из `app/meals.py`, нигде не хардкодить;
- позиции дня — только через `day_items()`, иначе потеряются замены;
- `menu_owner` может быть `0` (DEV-пользователь) — проверять `is not None`, а не на
  истинность;
- матчер `app/match.py` намеренно отклоняет совпадение по одному слову: иначе подпись
  «Сыр» цеплялась к случайному сыру. Если ссылка из плана не привязалась — это защита,
  а не баг; ставь URL прямо в `products.csv`.

**Безопасность**

- токены (`BOT_TOKEN`, `ANTHROPIC_API_KEY`, `MAX_BOT_TOKEN`) не выводить в чат и не
  вписывать самому — только маскированная диагностика; добавляет их владелец;
- репозиторий публичный, `.env` в `.gitignore`;
- анкета «О себе» в профиле конфиденциальна: видна только владельцу, в список
  пользователей не попадает.

## 10. Как со мной работать (предпочтения владельца)

Накоплено за несколько месяцев правок. Нарушать их — значит переделывать.

**Интерфейс**

- воздушно, ничего лишнего. Каждая кнопка должна себя оправдывать;
- формы добавления всегда спрятаны за кнопкой-пилюлей «+ Добавить …» со светлым
  пунктирным контуром, по размеру текста, не на всю ширину;
- никаких шапок на вкладках; на подэкранах — понятный заголовок и возврат свайпом;
- при возврате назад прокрутка восстанавливается на то же место;
- ссылки на товары живут только в «Закупках», не в меню дня;
- нижнее меню видно всегда (`position: fixed`);
- на «Сегодня» нет кнопок «Съедено», «Состав», «Готовить» и прогресс-бара — только
  название блюда, лёгкая ссылка «рецепт» строчными и количество.

**Разработка**

- любая существенная правка проверяется многоагентным ревью с опровержением находок
  (Workflow): сначала ревьюеры ищут дефекты, потом отдельный агент пытается каждый
  опровергнуть, и чинятся только подтверждённые. Это ловило блокеры, которых не видно
  глазами;
- новые фичи делать сразу для Telegram **и** MAX: фронт через обёртки (`tg` / `maxApp`),
  уведомления через `app/texts.py` и роутинг по `MAX_UID_OFFSET`;
- проверять живьём в браузере, а не только по коду;
- отчитываться честно: если что-то не доделано — говорить прямо.
